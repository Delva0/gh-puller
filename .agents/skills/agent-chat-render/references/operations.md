# 运维

## 状态、版本和边界

复用 [SKILL.md](../SKILL.md) 中用户已确认的工作区，逐次给工具传 `workspaceId`。
读取 `list_services` / `get_service` 后核对 repo、branch、plan 与 URL；`list_deploys` 查看正在构建、失败或 live 的提交。
先通过 HTTPS `/api/health` 区分应用是否可达，再决定看构建日志、运行日志还是应用事件。
仅查询地址或解释流程时保持只读；不要顺带清缓存、重启、重新部署、删除会话或轮换口令。

免费休眠可导致约一分钟的冷启动；外部页面尚未起来时，浏览器可能先显示 Render 的唤醒页面。
报告当前观测和下一次检查条件，避免连续发出长时间阻塞请求且不反馈进度。
失败有明确 HTTP / 平台状态时按该状态排查；没有响应时先保留“超时”，不据此猜测下载或部署百分比。

## 观测入口

| 入口 | 取得什么 | 取不到什么 |
| --- | --- | --- |
| Render `list_logs` | 带外平台构建 / 应用日志 | 不等于完整模型请求与工具轨迹 |
| Render `get_metrics` | 带外 CPU / 内存 / HTTP 指标 | 采样值不是瞬时峰值，也不是单次工具归因 |
| 应用 SSE / 导出的 `events.json` | 按会话编号的模型、reasoning、工具参数、结果、失败与结束状态 | 不是服务端进程 stderr 或 Render 构建日志 |
| 浏览器历史导出 | 非敏感设置、消息、展示事件 | 不包含可恢复 agent 的工具上下文或密钥 |

平台日志调用用 `resource: [serviceId]`，指标调用用 `resourceId: serviceId`；时间使用 UTC RFC3339。
先选择有关时间窗与类型，日志通常 limit 20，指标 resolution 60 秒即可；需要更细时本次连接器最小允许 30 秒。
15 秒请求曾被连接器 schema 拒绝，改成 30 即可，不需要升级套餐或让用户找管理员。

`list_logs` 曾返回 HTTP 503，内部为 Loki 502。此时应用 health 和真实查询仍正常。
说明平台日志暂不可用，可稍后有限重试或保留审查缺口；不能声称已经拿到了日志，也不能把它解释成应用崩溃。
模型工具错误的判断仍可依据用户提供的应用事件。

核对凭据是否泄漏时，不打印环境或上传原始凭据；导出脚本会检查提供的密钥不出现在保存的事件中。
本次应用关闭访问日志、不保存原始模型流、持久记录脱敏 JSONL；这些是代码行为，不能据此宣称平台所有日志均已审计。

## 会话和凭据

- 浏览器页面内的模型 / 平台凭据刷新后不回填；活跃服务端会话仍在时可继续使用。
- 不同浏览器的会话按 Cookie 所有者隔离。管理员重新登录也不能直接用新 Cookie 查看另一浏览器的轨迹。
  排查用户会话时获取问题原文、错误详情与其导出文件的本地路径。
- SSE 断开不会取消查询；重连按事件序号补发并去重。先看 `query/end`、连接提示与工具状态。
- 空闲会话 60 分钟后清理，运行中不按空闲超时删除；显式停止与删除走应用接口。
- 重启、重新部署或休眠会丢失内存中的工具上下文和临时文件。浏览器历史保留为只读，不从展示消息拼回上下文。
- 本项目的会话上限、运行并发、单次超时、事件 / ToolStorage 配额，以当前 `ServerSettings` 和 runtime 为准。
  遇到限制先识别错误来源；不要为清理测试会话删除用户其他浏览器的会话。

## 工具失败排查

先对齐原文问题、代码 SHA、backend、PTC、模型地址 / 名称、thinking 参数、步数和输出限制、平台凭据可用性。
同名 agent 在 DSL 与 REST、实验目录与主包不同版本之间，不能直接认定行为应完全一致。
读取 `tool/start` 的参数、对应 `tool/end` 的结果 / 错误和模型如何处理它；解释模型判断时查看相邻 reasoning。

本次 GitCode DSL 公网验收最终答案正确，但 11 次工具调用中有 6 次失败：
原生响应缺字段、两次语法错误、两次 DSL 字段错误、以及不存在的 `main` 分支 / README 的 404。
这些分别涉及来源数据、模型调用和工具 schema，不能统称为 Render 网络故障或“重构全部坏了”。
有效答案与执行失败分开记录，额外调用对耗时的影响也单独说明。
用户后来要求 GitHub / GitCode 默认 REST；该产品默认值调整不是修复所有 DSL 问题的证明。

## 常见现象与处理

| 现象 | 已验证处理 |
| --- | --- |
| Free Blueprint 拒绝 `maxShutdownDelaySeconds` | 移除字段，保留 Free，重新推送并让平台读取新提交 |
| 构建成功但修复未出现 | 核对线上 SHA、静态资源、安装文件；检查 uv 本地 wheel 缓存是否重建源码包 |
| `openai-codex-cli-bin` 下载久 | 检查 SDK 的锁定依赖与公共缓存；本机 CLI 不会替代 Python 发行包 |
| 首次 DSL 查询长时间不响应 | 检查 schema 是否在事件循环同步构建，查看 health 与取消响应；本应用已后台初始化 |
| 刷新后要求再次输入模型密钥 | 判断是新会话还是已失效服务端上下文；不从 IndexedDB 取回密钥 |
| 默认已改为 REST，旧会话仍是 DSL | 工具配置首次提交后固定；刷新并新建会话使用新默认值 |
| 流式输出把向上阅读的位置拉回 | 同时检查待执行的 animation frame、用户滚动方向和输出增长；已有浏览器回归覆盖 |
| 低内存或临时空间不足 | 查看平台指标与应用配额；记录具体请求规模，不用小型顺序查询外推重型并发容量 |

运维结论引用具体部署、UTC 时间窗、事件文件与行号或平台指标。
验证中断、日志接口不可用、未知费用和未验证的冷启动条件都保留为限制，不将模拟结果写成公网结果。
