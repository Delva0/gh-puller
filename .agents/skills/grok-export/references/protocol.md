# Source protocol and preservation

These endpoints were verified against Grok's own web client and a live public
share on 2026-09-22. They are implementation details, not a stable API contract.

```text
GET https://grok.com/rest/app-chat/share_links_data/<share-id>
GET https://grok.com/rest/app-chat/share_links_data/<share-id>?useChunk=true
GET https://grok.com/rest/app-chat/share_links/<share-id>/subagents/<conversation-id>
```

Keep the share ID unchanged, including its prefix. `sharedSubagents[].conversationId`
identifies public child conversations. Follow these records recursively and retain
statuses. The inspected subagent endpoint declares no chunk-mode parameter.

The older `/rest/app-chat/share_links/<share-id>` also returns data, but the client
identifies it as the variant that increments the view count. Prefer the data-only
endpoint. No pagination is declared for share data; a newly exposed continuation
marker requires investigation of the current client before claiming completion.

## Complementary views

The flat view contains `message`, `steps`, and metadata. Steps can include `text`,
`tags`, `toolUsageCards`, `toolUsageResults`, and search results. Tool text may use
`<xai:tool_usage_card>` XML with a call ID, name, and JSON arguments in CDATA.
Keep this text verbatim: an `OpenPage` XML argument can include `start_line: null`
and `pattern: null` even when its structured card omits them.

The chunk view can leave `message` and `steps` empty. Preserve `inputChunks` and
`outputChunks`, including `text.channel`, `metadata.stepId`, `toolUsageCard`,
`toolResult`, layouts, and unknown payloads. Source array order is authoritative;
step IDs are grouping metadata, not a safe sort key. Tool results can interleave.

`toolResult.toolCallId` links to `toolUsageCard.toolUsageCardId`. An OpenPage result
can use the `webSearch` result envelope; obtain the tool name from its call.
The exporter counts calls by response ID and call ID across both representations.

`CHANNEL_ASSISTANT_NOTETAKER_HEADER` is a displayed thinking header, not detailed
reasoning. `CHANNEL_ASSISTANT_RESPONSE` is response text. Preserve other channels
verbatim and inspect unfamiliar ones before interpreting their meaning. Thinking
timestamps alone do not expose a thinking transcript.

## Markdown format

Each source view has fetch provenance and its own original field ordering.
Each block is preceded by `<!-- grok-value PATH TYPE -->`, where PATH is a JSON
Pointer and TYPE is `json` or `text`. JSON blocks preserve structured values;
text blocks preserve individual strings. The text fence is longer than every
backtick run in its content. The newline before the closing fence is formatting,
not a change to the recorded text. Empty arrays, strings, objects, and nulls stay
in JSON blocks. Structural containers are announced with `grok-container` markers;
`grok-fields` blocks add unchanged fields to the indicated object.

The partitions can reconstruct each source document without losing a field.
The script's `read_documents` function verifies this by round-tripping the entire
Markdown before writing it. The optional `--raw-json` stores source body text and
parsed documents; it is not generated by default. Source body SHA-256 hashes in
the Markdown describe the fetched bytes after HTTP decompression, not wire bytes.

## Coverage and availability

Acquisition failures, missing flat/chunk views, response-ID disagreements,
unfetched subagents, malformed XML, and continuation markers require follow-up.
Missing parents can simply identify the beginning of a shared branch. Partial
responses, missing results, stream errors, and statuses remain visible.

`preview` and `snippet` are excerpts, not verified full historical tool bodies.
A length of exactly 1,000 characters is a truncation signal, not proof of omitted
content. Preserve `parsedText` separately when present. Never substitute a newly
downloaded page for a missing historical result.

All attachment records, embedded content, and asset references are retained. A
JSON capture does not necessarily include remote file bytes or a workspace's
filesystem. It also cannot prove availability of hidden prompts, private
reasoning, or unshared conversation branches.

For a browser-captured supplement, save the relevant response body and provide
another `--snapshot NAME=PATH`. Retain capture provenance; do not blend newly
fetched content into historical tool results. Cookies and authorization headers
are transport credentials, not agent context, and should not be embedded.
